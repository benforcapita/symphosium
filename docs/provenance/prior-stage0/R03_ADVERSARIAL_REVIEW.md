## Findings and decisions for CTO

1. **Reload atomicity and session scope (high).** LLD binds tracker/config per session and rejects scope changes while claims exist, but does not define the atomic boundary among file reload, scheduler claims, pending reads and tool dispatch. Specify one immutable generation tuple `(kind, org, project, assignee, credentials/reference)` captured at claim creation and carried through runner/tool calls. Decide whether a scope switch is rejected while *any* run or retry/blocked claim exists, and how operators drain those entries. A transition should recheck ticket membership under the bound generation inside its write transaction. A rejected reload must leave every previous setting intact.
2. **Agent transition authority (high).** “Only current ticket” still allows an agent to mark its own work Done/Cancelled. Define permitted target categories/states, whether workflow transitions require a human or state graph, and whether a moved, reassigned, newly blocked or terminal ticket rejects an in-flight agent mutation. This is a product/security decision; tests must encode it. Tool identity must derive from host run context, never JSON, prompt, model-supplied issue ID or session ID.
3. **Authorization transaction boundary (high).** Service authorization must use org and role from a fresh, revocable session lookup, then check row org/project and mutate within one transaction. Decide revocation semantics for an already admitted request and for SSE connections. Rows linked to a ticket (state, assignee, label, blocker, comment) need same-org checks, and project/team consistency needs constraints or locked checks. Out-of-scope IDs should yield 404 without existence disclosure.
4. **Concurrent scheduler and domain writes (high).** LLD says fresh blockers make running work non-dispatchable, but cancellation may race tool transition, retries and a stale completion. Define the precedence and generation fencing: after an archive, block, scope change or terminal transition, old attempt output must not revive a claim, write a misleading completion or remove a newer workspace. Tracker transport failure must preserve running/claim state pending retry, never be interpreted as empty candidates.
5. **Idempotency and lock ordering (medium).** Define whether the idempotency result stores the first response status and resource version, and whether a replay bypasses a now-stale supplied lock_version. Keep actor scope stable across session renewal but prevent cross-user key collision. Define a consistent project/ticket/dependency lock order to avoid deadlock during concurrent edge insert/delete and archive. DB uniqueness and activity/result commit must be one transaction.
6. **Filesystem isolation (high).** Separate worker identity is required in production; specify concrete owner/mode/ACL and mount policy for database credentials, session key, provider credentials, logs, backups, database socket and SSH credentials. Merely removing env vars does not prevent access to inherited FDs, process argv, readable config files, home directory, mounted sockets or hooks. Decide how worker receives only required agent auth without granting service secrets. Ensure local hooks and remote bootstrap run under the restricted identity.
7. **SSH lifecycle (high).** Define remote process group/session creation, cancellation timeout, kill escalation, disconnected transport handling, orphan detection and safe workspace cleanup. SSH forwarding must use an allowlist of environment variables and quote/encode arguments without remote shell interpolation. Define host key verification and accepted SSH config behavior. A dropped connection cannot count as successful completion.
8. **HTTP session and proxy edge cases (medium).** Specify trusted proxy configuration, cookie Secure behavior in TLS production, CSRF token rotation, login throttling scope and SSE revocation/origin revalidation. PM-enabled observability auth must cover every existing route including refresh/actions. Host-derived URLs must never enter proof links or redirect targets.
