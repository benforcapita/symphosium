## Blocking findings

1. **High — scope fence compares raw assignee text, not effective scope.** `rust/src/config.rs:224–228` resolves `provider.assignee: $ASSIGN` to `resolved_assignee`, but `scope()` at lines 320–333 reads the unresolved provider value. Changing `ASSIGN` between generations leaves `scope()` equal while active claims exist, so `reload.rs:100` accepts a dispatch-scope change forbidden by LLD3 §11.1. The same design needs an explicit resolved identity for every env-backed scope selector, not only assignee, before claim binding. Reproduction: isolated `effective_assignee_scope_changes_when_env_changes` fails because two settings with `ASSIGN=a` and `ASSIGN=b` compare equal. Fix: compare validated effective kind/org/project/assignee fields, capture that tuple in each immutable snapshot, and test reload rejection with an active lease and changed env. **Owner:** Senior1 R05; Senior2 re-review; QA2 independent retest.

2. **Medium — R05 config compatibility is incomplete and silently drops runtime policy.** `RawSettings` (`config.rs:94–102`) ignores `hooks`, `worker`, `observability`, `server`, and most `codex` settings. `RawAgent` omits `max_concurrent_agents_by_state`; `RawCodex` retains only `command`. A reference WORKFLOW with `codex.approval_policy: never`, sandbox policy and hooks passes `--check`, but the typed `Settings` cannot carry them into R12/R13. The reference defaults/validation at `workspace_and_config_test.exs:990,1301,1372,1418,1485,1542` and SPEC §§5.3–6.4 require these fields to be retained/validated for compatibility. Fix R05's config model and offline fixtures for documented defaults, aliases, env, per-state limits and policy passthrough; do not defer a knowingly lossy parser to runtime tickets. Configuration for new SQL/PM features can be added with R06/R07, but the existing runtime contract must be stable before downstream integration. **Owner:** Senior1 R05; QA2.

3. **Medium — blank default prompt loses ticket description.** `prompt.rs:4` contains only identifier/title. The reference explicitly includes `Body:` and the actual description, with `No description provided.` for absent bodies (`core_test.exs:1410,1434`). In the isolated copy, `default_prompt_keeps_reference_description` fails. Fix default text and exact output tests for present/missing body. Also expand parity tests for nested/date values and contextual strict-variable/parse errors (`core_test.exs:1327,1353,1374,1393,1453`); the current nine tests cover only one top-level render and one unknown field. **Owner:** Senior1 R05; QA2.

4. **Medium — required labels retain duplicates after normalization.** `config.rs:293–298` lowercases/trims but does not deduplicate. Reference `workspace_and_config_test.exs:990` expects `[' Symphony ', 'SYMPHONY', 'JavaScript']` to become `['symphony', 'javascript']`. Isolated `required_labels_deduplicate_like_reference` fails with `['symphony', 'symphony']`. Fix stable-order deduplication while retaining a blank label as a fail-closed entry. **Owner:** Senior1 R05; QA2.

5. **Medium — CLI parse/validation does not yet meet reference surface.** `cli.rs:26–63` accepts `--port 0`, a blank `--logs-root`, and any existing/nonexistent workflow path until `run`; it records `logs_root` and `port` but no configuration consumes them. The reference rejects blank logs root, requires a regular workflow file, expands paths and validates port through its runtime override (`elixir/lib/symphony_elixir/cli.ex`; `cli_test.exs:8,46,58,82,101,114,128`). Add parser/startup contract tests and represent validated option values in the startup context. The explicit `RuntimeUnavailable` result at `cli.rs:68–69` is an honest R05 boundary; running a scheduler belongs to R12 and is **not** this finding. **Owner:** Senior1 R05; QA2.

## Interface and risk notes

- `Tracker` (`tracker.rs:60–65`) correctly distinguishes an empty success from a typed transport error, but its comment does not enforce generation binding and it has no adapter/session object yet. R09/R12 must use a lease-bound adapter and discard superseded read results per LLD3 §11.1. Do not claim this behavior is implemented by the trait alone.
- `TrackerSettings.provider` and `resolved_api_key` are plain cloneable values without `Debug`; no direct secret Debug output was found in this patch. `TrackerError` accepts arbitrary `String` detail. Before provider clients land, add a synthetic-secret negative test for config/parser/client error surfaces and logs; I did not observe a leak in the nine tests.
- R06 can begin its schema work from the typed module boundary, but should not integrate against the present `Settings` as a final config contract. The missing runtime policy fields and effective scope identity affect downstream scheduler/runner behavior.
